# Two worlds on one box

Design spec, 2026-09-28. Builds on `2026-09-18-mods-design.md` and `2026-09-18-panel-v3-design.md`.

## Goal

Run a second Valheim world (`Iron Arbiters World`, an existing save) as a second container on the
same instance, with the same password, mods and drop rates, and show both worlds on the panel.

## Locked decisions

| Decision | Value |
|---|---|
| Config | `worlds: WorldConfig[]` replaces `worldName`. `WorldConfig { name: string; port: number }`. Names allow spaces: `^[A-Za-z0-9 _-]{1,32}$`, unique. Ports are even, between 2456 and 2470, unique; each world uses `port` (game) and `port + 1` (query). Value: `[{ name: 'OsrsNerds', port: 2456 }, { name: 'Iron Arbiters World', port: 2458 }]`. |
| Primary world | `worlds[0]` keeps everything the single world has today: container `valheim`, `/opt/valheim/config`, `/opt/valheim/data`, watcher unit `valheim-players.service`, parameter `/valheim/panel/players`, Steam name `serverName`. Nothing on disk moves. |
| Extra worlds | `slug = name.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')` (`iron-arbiters-world`). Container `valheim-<slug>`; `/opt/valheim/worlds/<slug>/config` and `/opt/valheim/worlds/<slug>/data`; watcher unit `valheim-players-<slug>.service`; parameter `/valheim/panel/players-<slug>`; Steam name `${serverName} - ${name}`. |
| Compose | One service per world in the same compose file and parameter. Extra services map host ports `<port>-<port+1>` to the container's `2456-2457/udp`; everything else (env, hooks, `env_file`, restart, `BEPINEX`) is identical. Discord hook messages read `Valheim <name> is up` and `Valheim <name> is shutting down`. |
| Firewall | One udp ingress rule per world for `port` to `port + 1`. |
| Mods | `valheim-fetch-config` runs `valheim-mods sync` once per world with that world's `--config-root` and `--install-root`, sharing `/opt/valheim/mods-cache`. Overrides apply to every world. It also creates missing world directories (`config`, `data`) owned by `1000:1000`. The world list is baked into the script at synth. |
| Watcher | `valheim-players` gains a third argument, the container name (default `valheim`). One unit per world, generated by `installScripts`. |
| Parameters | CDK creates the players parameter for every world in `ServerInstance` (`playersParameters: Map<slug, StringParameter>`), same initial value and grants as today. |
| Panel | Env `WORLDS`: JSON `[{ name, port, queryPort, playersParameter }]` in config order. `PanelView.worlds: WorldView[]` with `WorldView { name, players?, maxPlayers?, playerNames?, connectString, steamString }`. Top level keeps `players` (sum over worlds, `undefined` if every query failed) and `playerNames` (all worlds, sorted case-insensitively) so the hero and sleep line work unchanged. "Getting in" becomes one block per world: world name as the heading line, count and names, Join IP and Steam rows with Copy. `/status.json` gains `worlds: [...]` and keeps its existing fields. |
| Sleeper | Queries every world. `players` is the sum; `null` (keep the timer, never stop) if any query fails. Env `WORLDS` too. |
| World import | New private S3 bucket `Transfers` (objects expire after 7 days, removed with the stack). Instance role reads it. `npm run import-world -- "<name>" <file.db> <file.fwl>` uploads to `s3://<bucket>/worlds/<slug>/`, then runs an SSM command that stops that world's container if it exists, copies the files into `<config>/worlds_local/`, chowns them, and starts the container again. For a brand new world it runs before the first start. |
| Box size | `instanceType` stays a config value; Fayadh picks `m7a.large` or `m7a.xlarge`. The budget alarm moves with it. |
| Not in scope | Per-world Start and Stop, separate passwords, per-world mod sets, per-world schedules, world switching from the panel. |

## Behavior

### Server start

`valheim.service` starts every service in the compose file. Before it, `valheim-fetch-config`:

1. Fetches compose, secret, mods and overrides as today.
2. For each world: `mkdir -p` its `config` and `data` directories, chown `1000:1000`, then
   `valheim-mods sync <manifest> <overrides> --config-root <config>/bepinex --install-root <data>/bepinex/BepInEx --cache /opt/valheim/mods-cache`.

Each container updates Valheim on its own schedule and keeps its own backups under its `config`.
DLM snapshots of the data volume cover both worlds.

### Panel

`view()` queries every world's query port in parallel (`Promise.all`) and reads every players
parameter alongside the other parameters. The hero keeps the instance state. The sub-line uses the
summed count. Each world block shows `N vikings` and the names for that world, or "Nobody online yet".
The client script refreshes the per-world lines from `status.json.worlds` by index.

### Import

`scripts/import-world.ts` (AWS CLI, profile `valheim`):

1. Looks up the bucket name and instance id from stack outputs (`TransfersBucket`, `InstanceId`).
2. `aws s3 cp` each file to `s3://<bucket>/worlds/<slug>/<basename>`.
3. SSM `AWS-RunShellScript`: `docker stop <container>` if running, `aws s3 cp --recursive` into
   `<config>/worlds_local/`, `chown -R 1000:1000`, `docker start <container>` if it was running.
4. Prints what landed.

## CDK changes

- `lib/config.ts`: `WorldConfig`, `worlds`, validation, `slugify`, `worldPaths(world, index)`,
  `containerName(world, index)`; `worldName` removed.
- `lib/compose.ts`: services from `worlds`; `serverArgs` unchanged.
- `lib/network.ts`: `Network` takes `worlds`, adds one ingress rule per world; `GAME_PORT` and
  `QUERY_PORT` stay as the primary's values for the outputs.
- `lib/server-instance.ts`: `playersParameters`, grants for each.
- `lib/instance-scripts.ts`: per-world mkdir and sync lines; per-world watcher units through
  `lib/players-watcher.ts` (`playersWatcherUnit(region, container, parameter)` and
  `playersWatcherInstall(region, worlds)`).
- `lib/control-panel.ts`: `WORLDS` env for panel and sleeper (replacing `SERVER_HOST` plus port
  env only where the panel used them; `SERVER_HOST` stays), read grants on every players parameter.
- `lib/transfers.ts`: the bucket and the `TransfersBucket` output; role grant in `ServerInstance`.
- `lib/valheim-server-stack.ts`: wiring; outputs gain `WorldPorts` (`name: port` per line).
- `scripts/import-world.ts`, `package.json` script `import-world`.
- `server/valheim-players.py`: container argument.
- README: worlds section replaces the world import paragraph.

## Testing

  out-of-range or overlapping ports, `slugify` cases.
- `test/compose.test.ts`: two services, primary unchanged, extra service ports and volumes and
  Steam name, hook messages name the world.
- `test/user-data.test.ts`: two sync lines with distinct roots and the shared cache, mkdir lines,
  two watcher units with their container and parameter.
- `test/panel/players-watcher.test.ts`: container argument accepted in replay.
- `test/stack.test.ts`: two ingress rules, two players parameters, transfers bucket with expiry,
  panel env `WORLDS`, instance role reads the bucket, still exactly two `"Resource":"*"`.
- `test/panel/*`: multi-world view, status JSON shape, sleeper sum and null rule, html blocks.
- Post-deploy: both containers running, both A2S queries answer, panel shows two blocks, a friend
  joins `100.29.76.244:2458` with the same password and profile.
